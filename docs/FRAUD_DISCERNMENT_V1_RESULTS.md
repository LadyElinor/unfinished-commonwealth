# F1 discernment results and limitations

The [design and source audit](FRAUD_DISCERNMENT_V1.md) specify the rules and
historical case sources. These are 25 authored exposed scenarios, crossed with
six fixed policies for 150 deterministic runs. Twelve scenarios have a harmful
simulated outcome and thirteen are legitimate. This constructed prevalence says
nothing about the frequency of real scams. No models were trained or called.

| Policy | Harmful recommendations / 12 | Legitimate declines / 13 | Legitimate unresolved / 13 | Legitimate recommendations / 13 | Legitimate on time / 13 | Attempts | Observations |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Always recommend | 12 | 0 | 0 | 13 | 13 | 25 | 0 |
| Always decline | 0 | 13 | 0 | 0 | 0 | 25 | 0 |
| Surface cues | 9 | 5 | 0 | 8 | 8 | 25 | 0 |
| Document count | 12 | 0 | 0 | 13 | 13 | 25 | 0 |
| Always verify | 1 | 1 | 3 | 9 | 6 | 75 | 44 |
| Evidence gate | 1 | 1 | 3 | 9 | 8 | 57 | 26 |

Each run has the same four-attempt and two-observation ceilings. The first,
third and fourth controls also recommend two requests without matching standing
authorization. Always-verify and evidence-gate each retain six unavailable-channel
refusals. The [machine-readable report](../examples/discernment-v1-summary.json)
records each case-policy result, all totals, source hashes and replay digests.
Full journals are generated by the CLI; none of the refusals or costs is dropped.

## What the failures show

- **Compromised roots defeat the candidate.** Both simulated trusted channels
  confirm a harmful request. Their observations match a legitimate twin, so the
  evidence gate recommends it. Real authentication, compromise detection and
  independent operators are outside this experiment.
- **Abstention costs legitimate work.** Unavailable channels, expired evidence
  without a replacement, and absent authorization leave three legitimate cases
  unresolved. Absence of authorization remains a valid reason to defer; its cost
  is reported without calling it a permission failure.
- **Contradictory trusted records can obstruct a legitimate request.** The
  candidate declines the conflicting-record case. The model provides no automatic
  resolution, unlimited reviewer or free recovery that erases that result.
- **Verification can miss deadlines.** A new legitimate urgent request completes
  its recommendation at slot 3 against a slot-1 deadline. Available fresh cached
  evidence avoids unnecessary rechecking on other cases; always-verify loses two
  additional on-time legitimate recommendations. Costs were specified before
  scoring and were not tuned to produce a favorable result.
- **Surface suspicion is poorly discriminating here.** Urgency, warranty language
  and educational discussion of verification codes produce false alarms, while
  polished false invoices can pass. Two asserted documents give the document-count
  policy no advantage because these fixtures deliberately contain corroboration
  that is only apparent.

The evidence gate and the simpler always-verify control make the same final
recommendations on all 25 cases. Their difference is observation and delay cost,
not improved identification of fraud. This does not establish an institutional,
multi-agent or adaptive advantage. The constant-reject control avoids every
harmful recommendation by declining every legitimate request too.

These results test typed evidence checks, not comprehension of arbitrary text.
The prompt-instruction fixture is inert data by construction; success does not
establish general prompt-injection resistance. The source-status helper preserves
curator-supplied allegations, pleas, verdicts, acquittals, settlements, estimates
and administrative actions. It cannot determine whether an unknown webpage is
true or detect undisclosed overlap between amounts. Official provenance, coherent
procedure and matching hashes do not substitute for those missing capabilities.

## Reproduction

```bash
python scripts/verify.py
python -m commonwealth.discernment_v1 run .local/discernment-v1
python -m commonwealth.discernment_v1 replay .local/discernment-v1/journals/compromised-trusted-roots--evidence-gate.json
python scripts/package.py .local/discernment-package
```

Choose new output directories. Output publication preserves existing artifacts;
an interrupted writer may leave a lock file requiring operator review before
a retry. A hash chain is a reproducibility check, not authenticated provenance.

Validation on 2026-10-24 passed all 235 tests: 204 existing tests and 31 new
discernment/source-status regressions. JSON integrity and local documentation
links passed. Every one of the 150 journals replayed; independent output
directories were byte-identical. Tests retain compromised-source failure,
false alarms, incompatible totals, malformed input, resource exhaustion,
tampered history and failed artifact publication.

Offline source-archive verification and clean wheel installation passed,
including the 24-event workshop demo, 15 original comparisons, 432 D1 runs,
eight P1.1 traces, historical P1 replay, and all 150 F1 runs. Installed replay
preserves the compromised-source failure at head
`18c338103de8983784e3af846e6daa1e7ced2a886c507c429350f289edbb487f`.
Workshop, D1, P1/P1.1 source and their committed results/history are unchanged.
Hosted CI runs the same checks on Linux Python 3.11/3.12/3.13 and Windows
Python 3.12. The dangling-symlink preservation check is explicitly skipped on
hosts that do not permit creating directory symlinks; all 235 passed locally.
